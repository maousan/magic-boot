# 2026-04-23 库位状态真值表改造计划

## 目标
- 引入 `t_location_status` 作为亮灭灯唯一真值来源。
- 移除上传、完成、控制链路对 `CommonCountMap` 的依赖。
- 保持对外 API 兼容，确保请求/响应与核心错误文案不变。

## 实施步骤
1. 新增数据库迁移：创建 `t_location_status`，并从 `t_picking_upload_detail` 初始化回填。
2. 新增 `locationStatusUtils`，封装状态刷新、快照查询、亮灭灯分流。
3. 改造 `拣货数据上传.ms` 与 `拣货上传公共逻辑.ms`：reconcile 与亮灭灯决策切换到 `t_location_status`。
4. 改造 `拣货完成.ms`：提交完成后刷新状态表，并按状态表结果执行亮灭灯分流。
5. 改造 `亮灯灭灯控制.ms`：控制决策依赖状态表快照，不再使用内存计数。
6. 更新 trace 扩展字段：移除 `commonCount*`，改记录 `locationStatus` 快照。

## 验收
- 单用户未完成：绿色灯；多用户未完成：复合色；全部完成：关灯。
- 重传上传与重复完成不会导致状态漂移。
- 关键接口返回码与主要文案保持兼容。
