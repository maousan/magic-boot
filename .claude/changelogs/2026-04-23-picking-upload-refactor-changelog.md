# 2026-04-23 拣货数据上传接口重构变更日志

## 变更概述
- 重构 `拣货数据上传.ms` 为“主流程编排 + utils 函数库”结构。
- 新增上传专用公共逻辑文件：`拣货上传公共逻辑.ms`。
- 目标为降低脚本复杂度和脆弱性，同时保持外部行为兼容。

## 主要改动
- 上传接口主流程调整为：`prepare -> validate -> persist(transaction) -> reconcile -> dispatch -> trace -> response`。
- 将以下逻辑从接口脚本下沉到公共函数：
  - 入参与明细校验（含去重与错误消息生成）
  - 差量库位计算（added/removed/affected）
  - CommonCountMap 回填与移除
  - 单人/多人亮灯分流与异步派发
  - trace 持久化包装
  - 集合合并与日志摘要格式化
- 保留原有批量插入策略，未退化为逐条写入。
- 修复上传链路“全部完成不主动灭灯”问题：基于 `CommonCountMap` 回填结果，仅对用户数 `<=0` 的库位异步派发关灯。

## 兼容性说明
- 未修改 `/api/light/picking/upload` 的请求与响应结构。
- 保持原有返回码和关键错误文案语义。
- 保持 `status` 判定逻辑（按 `planQuantity` 与 `actualQuantity` 重算）。
- 保持亮灯颜色规则（单人默认 `GREEN`，多人 `BLUE`，用户映射优先）。

## 风险与注意事项
- 本次仅重构上传接口，未同步重构 `拣货完成.ms` 与亮灯控制脚本，后续可考虑复用同一套公共函数进一步降重复。
- trace、缓存回填、异步派发仍为“失败记录日志，不中断主响应”的策略。
